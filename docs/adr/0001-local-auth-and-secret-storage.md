# ADR-0001：本地鉴权与供应商密钥存储

- 状态：已接受
- 日期：2026-09-27
- 适用版本：CCDPH 0.3.2+

## 背景

CCDPH 是只监听回环地址的便携 Electron 应用。渲染进程需要访问本地 HTTP API、SSE 和终端流，同时不能把长期鉴权材料暴露在 URL、浏览器存储或日志中。供应商 API 密钥还需要兼顾 Windows 便携运行与其他平台的源码启动。

## 决策

1. 每次服务启动生成 32 字节随机启动令牌，只通过桌面入口 URL 的 hash 交给渲染进程。
2. 渲染进程立即用启动令牌调用 `/api/auth/session`，换取 `HttpOnly + SameSite=Strict + Path=/api` 的内存会话 Cookie；成功后清空内存中的启动令牌。
3. 所有 API 都接受该 Cookie，同时继续执行 Host、Origin、恒时比较和分桶限流。
   Cookie 与服务端随机值属于同一次应用启动：服务端令牌轮换意味着应用已重启，旧窗口不是受支持的存活状态；401 恢复失败时前端会明确提示重新打开 CCDPH。
4. Windows 供应商密钥使用当前用户 DPAPI 加密后写入 `api-auth.json`。
5. 没有可用系统安全存储时，密钥仅驻留当前进程内存，不写磁盘；退出后用户需要重新输入。
6. 无法解密的加密密钥库进入锁定状态，后续写入不得覆盖原文件。
7. 旧明文密钥迁移失败时允许主程序继续启动；若能移除旧文件，则密钥仅在本次运行可用；若连原文件也无法移除，则清空内存密钥并保持锁定。

## 结果

- URL、`sessionStorage`、`state.json` 和日志中不再保存启动令牌或供应商密钥。
- 页面刷新可依靠 HttpOnly Cookie 恢复 API 会话，不需要在 Web Storage 中保留令牌。
- 非 Windows 或受管控环境仍能使用应用内供应商，但密钥不会跨重启保存。
- Cookie 不是远程访问能力；本地服务仍不得通过反向代理公开。

## 未解决事项

- Dedicated 浏览器启用期间，回环 CDP 端口仍是 Playwright 集成的产品能力；生命周期管理负责防止停用或异常退出后的残留。
- CCDPH 主 EXE 当前没有 Authenticode 代码签名证书，运行时清单主要用于损坏检测而非建立完整的软件供应链信任根。
- 专用 Edge 只有在 PID 标记成功原子落盘后才被视为启动成功。若标记写入失败，CCDPH 会尝试结束进程并拒绝提交设置；极端情况下操作系统同时拒绝记录与终止进程，当前运行期仍会保留进程句柄并报错，但应用若随后被强制崩溃，未标记进程无法由下次启动自动定位。这是操作系统拒绝两条恢复通道时的剩余风险。
